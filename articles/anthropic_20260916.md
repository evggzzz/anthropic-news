### Messages APIのオンデマンド会話コンパクション（ベータ、2026-09-14）

長時間動くエージェントの会話は、履歴が増えるにつれて入力トークンの費用が膨らみ、いずれコンテキスト上限に達する。
この対策をこれまで開発者は自前で実装するしかなく、履歴の切り詰めや要約をアプリケーション側で行う必要があった。
今回の機能は、この圧縮（**コンパクション**）をAPI自身が担うようにするものだ。

使い方は次の流れになる。
ベータヘッダー `compact-2026-09-04` を付けたリクエストで、トップレベルの `compaction` パラメータを送る。
APIは送信済みメッセージを要約した署名付きの `compaction` ブロックを返す。
以降のリクエストでは、元のメッセージ群の代わりに、このブロックを先頭に置いて送信すればよい。
要約の生成はAPI側が行い、開発者は受け取ったブロックをそのまま再送する作りである。

設計上の要点が3つある。
まず、圧縮のタイミングは開発者が選べる。
自動圧縮を待つのではなく、タスクの区切りなど文脈を失っても困らないタイミングで履歴を圧縮できる。
リクエストはバックグラウンドでの実行も可能である。

次に、直近のターンを要約対象から外し、そのまま（word for word）保持できる。
最近の文脈の正確さを保ちながら、古い履歴だけを圧縮できる。

最後に、preserved thinking対応モデルでは、保持したターンのthinkingブロックも有効なまま維持できる。
思考の連続性を壊さずに圧縮を挟めるため、推論の質を落としにくい。

破壊的変更はない。
既存動作を変えないベータ機能の追加であり、試すのはベータヘッダーの追加だけで済む。

## ⌨️ Claude Code

対象期間内のリリースは、9月15日付のv2.1.272とv2.1.273である。

v2.1.273は、権限チェックの穴を塞ぐセキュリティ修正と、企業のゲートウェイ運用向けの道具立てが中心のリリースだ。

### v2.1.273（2026-09-15）

#### 権限チェックの抜け穴2件の修正

`permissions.blockReadsOutsideWorkingDirectories`（作業ディレクトリ外の読み取りをブロックする設定）のもとで、解析不能なBashコマンドがプロンプトをスキップする問題が修正された。
併せて、危険な `rm` を隠すサブシェルも塞がれている。
前者は確認を受けないままコマンドが実行される経路、後者は表示されているコマンドとは別に `rm` が走る経路である。
権限モデルを信頼して運用する環境では、優先して当てたい修正だ。

#### ゲートウェイ向けヒンターヘッダー（opt-in）

`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` を設定すると、Claude Codeのリクエストにヒンターヘッダーが付く。
`x-claude-code-request-class` をはじめ、エージェント種別、ツール実行時間、compactionの情報を含む。
Claude Codeのトラフィックを企業ゲートウェイで中継する運用では、リクエストの分類やルーティング、監視の判定材料に使える。
既定ではオフのopt-inであり、ヘッダーを増やさない通常運用には影響しない。

#### リモートコントロールセッションのフォークとMCP切断の通知

Claudeアプリから `--remote-control` セッションをフォークできるようになった。
フォークしたセッションはローカルのバックグラウンドで実行される。
進行中のセッションを分岐して別の作業に回せるため、リモートコントロールとローカル実行を組み合わせた使い方がしやすくなった。

MCPサーバーが切断され、再接続に失敗したときは、`/mcp` への導線付きで通知される。
切断に気づかないまま作業が止まり続ける状況を減らす修正である。

#### 2.1.268の「解析不能なBash行の拒否」をrevert

v2.1.268で導入された、解析不能なBash行を拒否する動作が取り消された。
`time -p make build` のようなコマンドが再びプロンプトを表示する。
安全性を上げるはずの変更が正常なコマンドの実行を妨げていたため、拒否からプロンプト確認へ戻した形である。

#### auto modeの分類器をローカルへ（挙動変更）

Bedrock / Vertex / Foundry上のauto modeが、ローカル分類器に切り替わった。
分類の判断がローカルで完結するようになる。
サーバー側の分類器を使い続けたい場合は、`CLAUDE_CODE_AUTO_MODE_SERVER=1` で戻せる。

#### そのほかの修正と改善

複数組織の運用や長時間セッションで響く修正が目立つ。

- 組織全体でSkillsを無効化した後も、claude.aiと同期したスキルが残る問題。回復可能なゴミ箱への移動で解消
- Bedrock / Vertex / Foundryの401/403エラーが誤って `/login` を案内する問題。エラーメッセージが資格情報またはゲートウェイ管理者を明示するようになった
- `/login`・`/upgrade`・`/extra-usage` がそれまでのthinkingを破棄し、キャッシュを書き直す問題
- サブエージェントの最終応答にusageデータやmodel idが含まれない場合に失敗扱いになる問題
- advisorツールのターンが倍のサイズでカウントされ、早期のauto-compactを引き起こす問題
- `scheduled_tasks.json` をコピーした後に、定期タスクが誤ったセッションで実行される問題
- SDK / stream-json出力で、実行中のバックグラウンド化の後にサブエージェントのメッセージが欠落する問題
- 長時間セッションの高速化。フックとサブエージェントの更新で全体の再処理をスキップ
- `OTEL_LOG_TOOL_DETAILS=1` のログが、実際のエージェント、スキル、プラグイン、MCPの名前を含むように
- Windowsで、マップドドライブ併用時のUNCパス検査を改善

UIと各連携も大きく動いている。
VSCode拡張は、組織でフィードバックが無効な場合に「Report a problem」が表示される問題と、Windowsでの赤い終了コードバナーを修正した。

### TypeScript SDK v0.3.273（2026-09-15）

目玉は `SDKUsageReport` の追加である。
アシスタントメッセージに `usage_report` という兄弟要素が届き、ヘッドレス実行の `/usage` の結果を含む。
内容はセッション合計、プランのusage行、追加usageをカバーする。
ヘッドレス実行では対話UIで `/usage` を確認する手段がなく、SDKを組み込むホスト側は利用量を取り出しにくかった。
この結果がメッセージストリーム側に流れてくることで、課金の確認やメータリング、利用状況の表示に利用できる。

そのほかの変更は次のとおり。

- バックグラウンドタスクがワーカープロセスの再起動で停止したとき、`task_notification` に `reason: "worker_restart"` が付く
- ホストのStopまたはSessionStartフックのコールバックがタイムアウトしたとき、トランスクリプトに1行の通知が出る
- タイムアウト超過のStop / SubagentStop / SessionStartコールバックがフック失敗として報告され、他のフックの決定を破棄する問題を修正。決定なしとして数えるようになった
- ブラウザのSSEトランスポートがスラッシュコマンド一覧のライブ更新（`system/commands_changed`）を落とす問題を修正
- Claude Code v2.1.273とパリティ

### Python SDK v0.2.153（2026-09-15）

システムプロンプトに `snapshot` オプションが追加された。
`SystemPromptPreset` に `snapshot` フィールドが加わり、新しい `SystemPromptCustom` 型辞書も定義された。
`snapshot=True` では、初回リクエスト時点のプロンプトをセッションが保持する。
`snapshot=False` では毎回プロンプトを再構築し、`append` するテキストを反復して調整する場面に向く。
利用にはCLI 2.1.257以降が必要で、同梱CLIも2.1.273に更新されている。

この変更の効き目はプロンプトキャッシングにある。
キャッシュは同一プレフィックスの再送でヒットするため、セッションを再開するたびにシステムプロンプトを組み直すとプレフィックスが変わり、キャッシュが効かなくなる。
初回のプロンプトを固定しておけば、再開をまたいでキャッシュヒットが続く。
SDKで長時間、マルチセッションのエージェントを回す場合、コストに直結する改善である。

- **URL**: https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.153
