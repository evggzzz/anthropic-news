### v2.1.269（2026-09-11）: プラグイン評価の基盤と長年の不具合修正

#### プラグインのevalを実行する`claude plugin eval`

新コマンド`claude plugin eval`は、プラグインのevalスイートをClaude Code上で実行し、再現可能なスコア付きの結果をJSONとHTMLのレポートとして出力する。
プラグインが正しく動くかの判断は、これまで作者的な動作確認と利用者の評価に頼るしかなかった。
同じevalスイートを同じCLIで誰でも実行でき、結果がスコアとして再現できるなら、プラグイン間の品質を同じ物差しで比べられる。
マーケットプレイスに並ぶプラグインが増えるほど、この種の共通基盤の有無が信頼を左右する。
配布側のツールに評価の仕組みを載せた最初の一歩と読める。

#### `/output-style`による出力スタイルの切替

`/output-style [name]`は、出力スタイルの一覧表示と切り替えを行う。
対話セッションに加えて、Remote Control、クラウド、headlessの各セッションでも動作する。
出力スタイルは応答の書式を変える仕組みで、自動実行のパイプラインでもタスクごとに書式を切り替えられる意味がある。
あわせて、プロンプトと応答だけを表示する`/focus`ビューを提案するスピナーチップも追加された。

#### Bash経由の編集にdiffを表示

Bashツールがファイル編集を扱った際、変更ファイルのdiffを結果に表示するようになった（設定`bashEditDiffEnabled`）。
Editツールによる編集はdiffとして可視化される一方で、Bash経由の編集は結果画面から見えなかった。
変更を確認する手段が編集の経路によって異なるのは、レビューの抜け穴になる。
この差が埋まり、編集が見えない経路を通らなくなった。

#### テレメトリと実行上限の環境変数

観測と実行の上限を広げる環境変数が3つ追加された。

- `OTEL_METRICS_INCLUDE_REPOSITORY`: OpenTelemetryのメトリクスとイベントに`vcs.*`のリポジトリ属性を付与する
- `CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS`: LLMゲートウェイの`/v1/models`探索のタイムアウトを延長する（デフォルト3秒）
- `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`: Workflowツールの同時エージェント数上限を1〜256の範囲で引き上げる

1つ目は、複数リポジトリで利用状況を集計する組織に効く。
どのリポジトリの作業がリソースを消費しているかを、テレメトリから追跡できる。
2つ目は、応答に3秒以上かかるゲートウェイでモデル一覧の取得に失敗する環境向けである。
3つ目は、Workflowツールで多数のサブエージェントを並列させるワークロードの上限を緩める。

#### 権限ルールの厳格化（挙動変更）

運用に響く可能性が高いのは、権限まわりの挙動変更である。

`!`で始まるdeny/ask権限ルールは、書き込まれた設定ソース内でのみ適用されるようになった。
裸の`!`否定は無視される。
設定ファイルをまたいで否定ルールを効かせてきた運用では、除外が働かなくなるため、ルールの置き場所を見直す必要がある。

Bashの`tee`先ファイルに、`Edit()`のdenyルールと書き込みパスの検査が適用されるようになった。
`Bash(tee:*)`のallowルールは、作業ディレクトリ外への書き込みをカバーしなくなった。
`tee`で権限の外のパスにデータを書き出す経路がdenyルールで塞がれる一方で、正規の運用で作業ディレクトリ外に`tee`していたコマンドは、追加の権限設定を求められる可能性がある。

帰属表示のリマインダーが、CLAUDE.mdやメモリの「commit/PRに帰属表記しない」ルールを上書きしなくなった。
managed settingsで設定された行は引き続き有効である。
コミットメッセージの規約をCLAUDE.mdで管理しているチームでは、意図しない帰属表記の混入が減る。

そのほか、クラウドセッションでclaude.aiから同期したスキルは`anthropic-skills:<name>`形式に命名変更された。
bare名も他と衝突しなければ引き続き有効である。
`/ultrareview --post`は2つ目のクラウドセッションを起動せず、結果到着時にPRコメントを直接投稿してリンクを表示するようになった。

#### 信頼性の修正

修正の塊も厚い。

出力トークン上限で打ち切られ、自動再開された次のターンで、プロンプトキャッシュが部分的に失效する問題が修正された。
キャッシュが効かない部分は入力の再処理と再課金を伴うため、長文を扱うセッションではコストと遅延の両方に効く修正である。

`/goal`が、APIエラーやネットワーク断、トークン上限の後にサイレントに停止する問題が修正された。
バックオフ付きのリトライ、または理由付きの一時停止に変わる。
長時間回すゴール追跡のセッションが、知らないうちに止まっていたという事態が起きにくくなる。

日本語の利用者に直結するのはプロンプトサジェストの修正である。
日本語、中国語、タイ語など単語間にスペースを置かない言語でプロンプトサジェストが落ちる問題が修正され、日中韓のサジェストフィルタリングも改善された。
日本語入力中にサジェストが出ない状態が続いていた問題がようやく解消される。

そのほか、「Prompt is too long」でセッションが恒久的に固まる問題（主に巨大プロンプトのAgent SDKセッション）と、モデル切り替えやリトライ中に再開したheadlessセッションがターンの応答を失う問題が修正された。
端末側では、kittyプロトコル端末のF1/F2/F4、stのDelete、rxvt-unicodeのAlt+矢印、WezTermのShift+句読点（2.1.247での回帰）が直る。
CMYK JPEGが「cannot decode」で添付に失敗する問題も修正された。

#### VS Code拡張: エージェントマップと設定ダイアログ

VS Code拡張には、エージェントマップ、Hooksダイアログ、権限ルールダイアログが揃った。
エージェントマップはフッターの「N agents」ピルから開く。
エージェント別のカード、Stop agent、読み取り専用のトランスクリプトが揃い、複数サブエージェントの動きを個別に止めながら追える。
HooksダイアログとPermission rulesダイアログは、ユーザー、プロジェクト、ローカルの各設定を閲覧、追加、編集、削除する。
設定ファイルを直接編集していた作業がGUIに置き換えられる。
Focusビューでは、実行中サブエージェントのライブ進捗行も表示される。
ドキュメントやメッセージをユーザー以外の読み手向けに書く場合に、その読み手を明示する改善も入った。

#### Claude Code on the web

クラウドセッションで、Claudeが読む前にキューのメッセージを取り戻せるようになった。
Escまたは↑でメッセージボックスに復帰できる。

サブエージェントを使うルーチン実行が実際より早く完了扱いになる問題なども修正された。

### TypeScript v0.3.269（2026-09-11）: 権限の正確さと停止の解消

中心は権限まわりの修正とハングの解消である。

`result.permission_denials`から、パススコープのdenyルールでブロックされたRead、Edit、Writeの呼び出しが漏れる不具合が修正された。
denyで止めた操作が監査ログに載らない状態は、権限運用の信頼性を直接損なう。
ログの完全性が回復した。

ホスト起動のMCPサーバーのOAuth認可フローが、応答の遅い認可サーバーを待っている間に、割り込みや権限応答を止めてしまう問題も解消した。
OAuth待ちでSDK全体が固まると、ホスト側は応答も中断もできない。
この経路の停止が切れた。

挙動変更はPlan modeの権限チェックである。
skip-permissionsフラグを指定していても、書き込み操作は`canUseTool`を通るようになった。
フラグに残された役割は、後から`bypassPermissions`へ切り替えることを許可することだけである。
権限の最終決定をSDKホスト側が握る方針が、より明確になった。

そのほか、partial messagesを有効にしたランでは、`user_message_uuid`、`user_message_uuids`、`resume_reason`が、ターン最初のfinished assistantメッセージにも付くようになった（従来は開始のstreamイベントのみ）。
CLIがバックグラウンドのサブエージェントを復帰させたとき、`task_started`と`task_notification`に`tool_use_id`が含まれるようになった。
そのエージェントの直近の呼び出しidで追跡できる。
全体としてClaude Code v2.1.269とのパリティ更新である。
