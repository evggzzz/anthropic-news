## ⌨️ Claude Code

今週はv2.1.265とv2.1.266の2版が同日にリリースされた。
v2.1.265が機能強化中心の大規模版、v2.1.266がその退行を修正する緊急版で、実質的に1組のリリースとして扱うべき内容である。

### v2.1.266（2026-09-08）: ゲートウェイ退行の緊急修正

v2.1.265で、非公開の環境変数`CLAUDE_CODE_USE_GATEWAY`を単独で設定しただけでもCloudゲートウェイへのサインインが強制される退行が発生した。
この変数は単独では無視されるのが仕様で、本来はAPIキーや`apiKeyHelper`、カスタム認証ヘッダーとの併用構成で使うものだ。
退行の影響を受けた環境では、"Not signed in to the Cloud gateway" エラーで全リクエストが失敗する。
ゲートウェイやプロキシ経由でClaude Codeを使っている組織がv2.1.265に上げた場合、v2.1.266への即時更新は実質必須と考えてよい。
設定の変更は不要で、変数が単独で無視される挙動も従来どおりに戻っている。

- **リリース日**: 2026-09-08
- **URL**: https://github.com/anthropics/claude-code/releases/tag/v2.1.266

### v2.1.265（2026-09-08）: 機能強化中心の大規模版

#### 非対話セッションで`cd`が保持される

`-p` + stream-json、Agent SDK、クラウドセッションといった非対話セッションで、シェルの作業ディレクトリがメッセージごとに初期ディレクトリへ戻されなくなった。
従来は1ターン内で`cd`しても次のメッセージで`cwd`に戻るため、スクリプト側で毎回移動し直すか絶対パスで回避する必要があった。
リポジトリのサブディレクトリに入って作業を続けるような使い方で、ターンをまたぐ状態がそのまま保持される。
ヘッドレス実行と対話セッションの挙動の差が縮まり、長時間の無人実行が書きやすくなった。
後述のAgent SDK v0.3.265は、この修正のパリティ取り込みでもある。

#### `--plugin-dir`のフォルダ指定とプラグイン運用

`--plugin-dir`で個別プラグインではなくフォルダを指定できるようになった。
マニフェストを持つ子フォルダが個別のプラグインとして読み込まれ、実行中の追加・削除も検知される。
ローカルのプラグイン群を1つのディレクトリでまとめて管理でき、開発中のプラグインの読み込み直しが楽になる。
あわせて、プラグインパスのバックスラッシュでmacOS/Linuxのシンボリックリンク閉じ込みチェックをすり抜ける問題も同版で修正された。

#### ツール結果のディスク保存に1GB上限

ディスクに保存されるツール結果に1GBの上限が導入された。
切り詰められた場合は会話内のプレビューにその旨が明記される。
巨大なログや生成物を扱う長時間セッションで、ディスク消費とコンテキストへの取り込みすぎの両方に歯止めがかかる。

#### セキュリティ・認証まわりの変更

Artifactツールで他人のアーティファクトを読む際の扱いが変わった。
信頼できないコンテンツとして処理し、埋め込まれた指示をそのまま中継せず、検知した場合は警告する。
他ユーザーが作成したArtifactを経由したプロンプトインジェクションへの防御で、エージェントに外部コンテンツを読ませる運用では効いてくる変更だ。
サインインが必要なリモートMCPサーバーへのOAuthクライアント登録も、実際に認証する時点まで遅延される。
認証しないサーバーの登録が残らなくなり、余計な登録要求が減る。
管理設定面では、`forceLoginGatewayUrl`を持つマシンが起動時からClaude appsゲートウェイセッションになるようになり（`forceLoginMethod: "gateway"`と同挙動）、ゲートウェイセッションのOpenTelemetryエクスポート先もゲートウェイ中継を経由しないmanaged settings指定のコレクターへ変わった。

#### その他の変更

- `--worktree`がgit 2.32以上で並列チェックアウトになり、大型リポジトリの起動が速くなった
- `/workflows`のエージェント詳細にツール呼び出しの実行中/失敗/完了表示とサブエージェントのタスクリスト表示が追加され、Enterで展開できる
- スラッシュコマンドの文中入力時に候補がリスト表示になり、プラグインスキルを裸の名前でも呼び出せる
- レガシーHTTP+SSEトランスポートしか話さないMCP `http`サーバーが接続できない問題を修正し、MCP仕様どおりSSEへフォールバックするように
- 画像処理をランタイム内蔵の仕組みに変更し、一時ディレクトリへのネイティブイメージモジュール展開を廃止
- 2キーショートカットがtmux内など打鍵間隔1秒超で静かにキャンセルされる問題を修正（3秒待ち、タイムアウト時は通知）
- `/model opusplan[1m]`が"Model not found"で拒否される問題を修正
- advisorツールの採用判断がリクエストごとに再決定される問題を修正（判断は1回にまとめ、変わった時点で会話内で告知）
- ワークフロー実行のコンテナ再起動後の再開を修正。実行ジャーナル欠落時は全エージェント再実行ではなく明確なエラーで失敗する
- WindowsのAppContainer/制限トークンサンドボックス内でRead/Write/Editが全ファイルを拒否される問題を修正
- `claude-api`スキルのエラーコード参照を修正（モデルアクセス失敗は404、利用不可betaヘッダーは400）
- `/login`・`/model`・`/clear`の表示や動作の不具合を複数修正（ゲートウェイ再ログイン時の誤エラー、設定書き込み失敗の隠蔽、Remote Controlからの`/clear`がフック待ちで止まる等）
- [VS Code] 非アクティブセッションの自動アーカイブを追加（新設定 "Archive inactive sessions"、既定14日）。Reload Window後のサイドバーチャットが空白になる問題も修正

### TypeScript v0.3.265（2026-09-08）: `user_message_uuid`の拡充と`cd`保持

応答の起因を追跡するための`user_message_uuid` / `user_message_uuids`の付与範囲が広がった。
合成ターン（`isSynthetic: true` + `uuid`指定のメッセージ）の最初のreplyとresultに加えて、resumeなどClaude Code自身が開始したターンの最初のreplyとresultにも付くようになる。
付与タイミングも「ターンごと1フレーム」から「応答対象メッセージが変わった時点の最初のreply」に変わり、ターン途中で取り込んだユーザーメッセージと応答の対応が取れるようになった。
スラッシュコマンドのようにAPIリクエストを伴わないターンで、成功resultに`user_message_uuid`が欠落する問題も修正されている。
イベント駆動で複数の会話を束ねるエージェント実装では、応答とリクエストの突き合わせが正確になる変更だ。
加えて、マルチターンセッションでシェルの作業ディレクトリが毎ターン`cwd`オプションに戻される問題が修正され、`cd`がターン間で永続化する。
これはClaude Code v2.1.265の同名修正のパリティ取り込みで、CLIとSDKでヘッドレス実行の挙動が揃ったことを意味する。
